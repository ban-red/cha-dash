## Shared contracts (wave 4)

### Code layout
Following [03 · Architecture → Repository layout](03-architecture.md#repository-layout-monorepo):
- `internal/integration`: the types every integration implements (`Integration`, `Instance`, `Manifest`, capabilities, `TestResult`, the fact emitter) and the registry.
- `internal/runtime`: the per-instance coordinator (jittered polling of what's watched, backoff, auth errors → Repairs), and the per-instance HTTP client (TLS policy: CA pin / trust on first use / insecure; session cache; timeouts).
- `internal/spec`: the Tier 1 declarative spec engine (gjson + expr-lang).
- `integrations/<id>/`: Tier 0 integrations. `specs/<id>.yaml`: bundled Tier 1 specs.
- `internal/importer/homepage`: the Homepage importer.

### Integration IDs
The importer, the framework and wave 5 all use these IDs:

`checks` · `proxmox` · `pbs` · `docker` · `traefik` · `unraid` · `opnsense` · `frigate` · `uptimekuma` · `homeassistant` · `plex` · `sonarr` · `radarr` · `prowlarr` · `qbittorrent` · `immich` · `tautulli` · `bazarr` · `mealie` · `linkding` · `karakeep`

### Instance config keys
Every instance has `url` (where it applies) and `tls` (`{"mode": "verify" | "pin" | "tofu" | "insecure", "pin": "<sha256>"}`). **Identifiers are config, not secrets:** `token_id` and `username` are plain values (the API may still mask them), and only passwords, keys and tokens go in the vault. Vault names are `instance/<instance id>/<field>`; config holds `"${secret:instance/<instance id>/<field>}"` in their place, resolved only when handed to the integration. The other keys:

| Integration | Config | Secrets (write-only, kept in the vault) |
|---|---|---|
| `checks` | `targets: [{name, kind: http\|tcp, url\|host, port, expect_status, interval_s}]` | none |
| `proxmox`, `pbs` | `url`, `token_id` | `token_secret` |
| `docker` | `endpoint` (`tcp://…` or `unix://…`) | none |
| `traefik` | `url`, `username` (optional) | `password` (optional) |
| `unraid` | `url` | `api_key` |
| `opnsense` | `url` | `key`, `secret` |
| `frigate` | `url`, `username` (optional) | `password` (optional) |
| `uptimekuma` | `url`, `slug` | `key` (optional) |
| `homeassistant` | `url` | `token` |
| `plex` | `url` | `token` |
| `sonarr`, `radarr`, `prowlarr`, `bazarr`, `tautulli`, `immich`, `karakeep` | `url` | `api_key` |

### HTTP
JSON bodies; every route below needs the owner's session.

**Integrations**
- `GET /api/integrations/catalog` → `[{id, name, icon, version, tier, capabilities, config_schema}]`. `config_schema` is JSON Schema; secret fields are marked `"writeOnly": true`.
- `GET /api/integrations/instances` → `[{id, integration, name, status, version, last_ok, last_error, warnings}]`.
  - `status` is one of `ok`, `degraded`, `repair`, `error`, `disabled`.
  - `warnings` are `[{code, severity, message}]`.
- `POST /api/integrations/instances` `{integration, name, config, secrets}` → 201 `{id}`.
- `PUT /api/integrations/instances/{id}` `{name?, config?, secrets?}`; `DELETE /api/integrations/instances/{id}`.
- **Secrets are write-only:** responses only ever show `{"<field>": {"set": true}}`.
- `POST /api/integrations/test` `{integration, config, secrets}` (unsaved), and `POST /api/integrations/instances/{id}/test` → `{ok, version, latency_ms, grants, warnings, error}`.
  - `grants` is what the credential can actually do, read back from the source where it can tell us (Unraid's `me`, PVE `/access/permissions`, OPNsense's ACL-filtered menu).
  - Any write grant on a read-only connection is a warning.

**Passkeys** (go-webauthn v0.18.2; merged, see [`internal/README.md`](../../internal/README.md))
- **Discoverable credentials.** The RP ID and origin come from `CHADASH_PUBLIC_URL`. WebAuthn needs HTTPS or `localhost`.
- **Register:** `POST /api/auth/passkeys/register/begin` → `{publicKey}` (creation options, base64url); `POST /api/auth/passkeys/register/finish` (the attestation) → 201 `{id, name}`.
- **Sign in:** `POST /api/auth/passkeys/login/begin` → `{publicKey}`; `POST /api/auth/passkeys/login/finish` → 200 plus the session cookie.
- **Manage:** `GET /api/auth/passkeys` → `[{id, name, created_at, last_used_at}]`; `PATCH /api/auth/passkeys/{id}` `{name}`; `DELETE /api/auth/passkeys/{id}`.

**Import**
- `POST /api/import/homepage?dry_run=1` `{services_yaml, docker_yaml, settings_yaml}` → `{plan, hints, unmapped}`.
  - `plan` holds the board with its layout document, the instances (with the names of their secret fields), and the number of secrets moved.
- The same call without `dry_run` applies the plan in one transaction:
  - creates the board and the instances;
  - moves secrets into the vault;
  - returns `{board_id, instance_ids}`.
- The acceptance test is [`testdata/importers/homepage/dogfood`](../../testdata/importers/homepage/dogfood/README.md). **Merged:** all criteria pass (21 instances, 18 secrets, zero unmapped, a re-import changes nothing); the mapping table is in [`internal/importer/homepage/README.md`](../../internal/importer/homepage/README.md).
- `GET /api/import/homepage` returns the last import's record. Until wave 6 gives tiles a config home, that record is where tile names, icons, links and bindings live; entries with no catalog widget become the generic `service` tile.

### Realtime
In real (non-demo) mode, instances write into the same topics the demo uses:
- **`graph`:** resources and relations.
- **`metrics`:** series, keyed `<resource id>#<metric key>`.
- **`inbox`:** repairs and problems, as incidents.

So the web app treats demo and real data the same way.

Notes for wave 5:
- **Routes beyond the list above.**
  - `GET /api/integrations/instances/{id}` returns `config` (never secrets) and `secrets: {field: {set}}`.
  - PUT keeps secrets it isn't sent; `null` or `""` clears one.
  - `POST /api/integrations/test` also takes `{instance_id, config?, secrets?}` and fills in stored secrets.
  - `GET /api/integrations/instances/{id}/diagnostics`.
- **Status fields.** `last_error` is the message, with `last_error_code` and `last_error_at` beside it.
- **Graph ids.** `integration:<instance id>`, and `check:<instance id>/<target slug>` with the target name as the resource name.
- **Repairs** are `<instance id>.repair`, with `facts.instance`, `facts.field`, `facts.status` and `facts.code`. The phases are `open`, `fixing` and `resolved`.
- **Demo mode.** Instances run against a private topic set, so nothing reaches the Demo Home.
- **The wave 5 checklist** is in [`internal/README.md`](../../internal/README.md). Contract tests use `internal/integration/integrationtest` against `testdata/integrations/<id>/`.
- **Known gap.** Tile icons from other origins can't load under the CSP, so tiles show monograms until the hub caches icons.

## From the spikes (carry into wave 5)
- **Proxmox:** version adapters for mixed 8.4 and 9.x. Guest IDs are scoped to the cluster, not the node. A read-only token can't see backups or pending updates.
- **Docker:** a server-side event filter, and a full re-list on reconnect. The proxy probe has three tiers. A 403 from the proxy means "capability not granted", not an error.
- **Traefik:** resolve backend URLs rather than trusting labels; there's an nginx-proxy hop. Keep the open URL and the poll URL separate.
- **Unraid:** require API 4.37.4 or later. Never poll `disks` (it wakes spun-down drives). Autostart joins Docker by container ID.
- **OPNsense:** open the SSE stream only while a tile is on screen. Accumulate the 30-day totals in the hub.
- **Frigate:** live state over the `/ws` WebSocket. Raise a hint when the internal port is reachable as an anonymous admin.
